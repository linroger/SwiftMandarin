### 2026-07-21T14:27:39Z — `codex/async-audio-session`

- Bug: iOS 27 Thread Performance Checker reports synchronous `AVAudioSession.setActive` calls from the `@MainActor` speech router, risking UI hangs during local and MiniMax playback activation/deactivation.
- Baseline: clean isolated worktree at current `origin/main` commit `bd8acb1`; the unrelated dirty primary checkout remains protected.
- Root cause: `SpeechService.configureAudioSessionForPlayback()` and `deactivateAudioSessionIfIdle()` synchronously mutate session activation on the main actor. The Xcode 27 SDK provides async `activate(options:)` and `deactivate(options:)`, both returning `Bool`; the iOS 17 deployment target requires a non-main compatibility path.
- Concurrency risk: a direct fire-and-forget conversion can let stale speech deactivation land after recording or source-audio playback takes ownership. Pending playback activation must also remain request-scoped so a stopped/replaced request cannot begin late.
- Tests pending: deterministic activation ordering, cancellation/replacement, idle deactivation, source handoff, source integration guard, and fresh macOS/iPhone/iPadOS 27 builds.
- Next steps: implement one ordered audio-session transition boundary, route speech playback through an awaited request-owned activation gate, then complete regression and platform gates.

### 2026-07-21T14:40:50Z — implementation milestone

- Implementation: added one FIFO `AudioSessionCoordinator` for spoken playback, source preview, clip recording, and live recognition. iOS 27 uses async `activate`/`deactivate` with Boolean-result validation; iOS 17–26 uses the legacy blocking calls only on a private serial queue; macOS is a no-op.
- Lifecycle hardening: all three services now use pre-created owner tokens. Local and MiniMax playback, capture, preview, and recognition start I/O only after acquisition and reject stale/cancelled owners. Only the current owner may enqueue a real deactivation.
- Recognition hardening: activation moved ahead of engine I/O, concurrent starts/stops are state-guarded, and an old stop no longer clears/releases a newer engine owner.

### 2026-07-27 — structured AI translation output

- Bug: a translation surface rendered rambling model prose (commentary/analysis, first-person text) instead of a translation.
- Root cause: translation was the only AI feature with no output contract. All three providers returned the raw completion, so a model that summarized instead of translating, or a thinking model that emitted inline `<think>` reasoning, had that text displayed, spoken, and saved to history. `CloudAIService.translate` also capped output at 2048 tokens, truncating long passages.
- Change: shared one-field envelope + parser (`SwiftMandarin/Services/AIResponseParsing.swift`). Apple Intelligence uses `@Generable` guided generation, Ollama a constrained JSON schema, cloud `jsonMode` + the prompt contract; all three parse through `AITranslationResponseParser`. `CloudAIService.chat`/`chatTurns` now strip inline reasoning for every feature. OCR cleanup got the same treatment. Token budget scales to 8192.
- Files: added `AIResponseParsing.swift`; updated `AIExplanationPromptBuilder.swift`, `CloudAIService.swift`, `OllamaService.swift`, `AIWordExplanationService.swift`, `AIProviderConfigView.swift`, `Localizable.xcstrings`, `scripts/test-ai-prompt-contracts.sh`, `scripts/ai-prompt-checks/AIExplanationPromptChecksRunner.swift`, `init.sh`, `feature_list.json`.
- Tests: `zsh init.sh` green — 191/191 MiniMax, 27/27 audio-session, 124/124 AI prompt+parsing, 22/22 provider wiring. The AI contract script is now part of `init.sh`. Xcode 27 macOS and generic iOS Simulator Debug builds succeed with zero warnings/errors. Three mutation tests confirmed the new checks fail when the wiring or parsing is removed.
- Not done: no live provider call was made (no API keys used). Live QA with a thinking model on a long article, and the Apple Intelligence path on an eligible device, remain worthwhile before release.

### 2026-07-27 — translation study notes, transcription repair, AI transcription

- Three requests in one: (1) have the AI explain its translation, including the important characters/phrases, in the structured output, with a prompt that works for long and short inputs and skips easy characters; (2) audio transcription doesn't work; (3) add AI transcription and translation.
- (1) The Iteration 27 translation envelope now also carries `explanation` and `keyTerms`, so the notes cost no extra round trip on the AI path. New `AITranslationContext` supplies the direction plus the learner's native language; `AITranslationPromptBuilder.studyNotesContract(for:)` scales the term count with passage length (none → 2-4 → at most 8, never padded) and names the elementary vocabulary to skip per language. New `TranslationNotesView` shows the notes on Translate and Multimodal with one-tap save to the vocabulary book; Apple's on-device translation path gets an explicit "Explain this translation" button instead of a silent billed call.
- (2) Root cause was three defects in `AudioTranscriptionService`: on-device recognition was forced whenever `supportsOnDeviceRecognition` was true (which does not mean the locale's assets are installed) with no server fallback; `isAvailable` was checked immediately after constructing the recognizer, when it is transiently false; and a request that Speech never answered hung forever. Fixed with an on-device → server retry, a 3 s availability poll, a 120 s deadline, punctuation, and error domain/code in the message.
- (3) New `AudioTranscriptionEngine` (Apple Speech / AI provider) in `AIModelSettings`, `CloudAIService.transcribeAudio` speaking OpenAI's multipart `/audio/transcriptions`, an engine picker and editable model field in the audio pane, an engine-specific privacy notice, and Retry-with-AI buttons after an Apple Speech failure.
- Files: added `TranslationNotesView.swift`; updated `AIExplanationPromptBuilder.swift`, `AIResponseParsing.swift`, `AIWordExplanationService.swift`, `CloudAIService.swift`, `OllamaService.swift`, `AudioTranscriptionService.swift`, `AIModelSettings.swift`, `MultimodalAudioInputView.swift`, `TranslateView.swift`, `PhotoTranslateView.swift`, `AIProviderConfigView.swift`, `Localizable.xcstrings` (20 new keys with zh-Hans), the checks script and runner, `feature_list.json`.

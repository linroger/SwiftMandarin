### 2026-07-21T14:27:39Z — `codex/async-audio-session`

- Bug: iOS 27 Thread Performance Checker reports synchronous `AVAudioSession.setActive` calls from the `@MainActor` speech router, risking UI hangs during local and MiniMax playback activation/deactivation.
- Baseline: clean isolated worktree at current `origin/main` commit `bd8acb1`; the unrelated dirty primary checkout remains protected.
- Root cause: `SpeechService.configureAudioSessionForPlayback()` and `deactivateAudioSessionIfIdle()` synchronously mutate session activation on the main actor. The Xcode 27 SDK provides async `activate(options:)` and `deactivate(options:)`, both returning `Bool`; the iOS 17 deployment target requires a non-main compatibility path.
- Concurrency risk: a direct fire-and-forget conversion can let stale speech deactivation land after recording or source-audio playback takes ownership. Pending playback activation must also remain request-scoped so a stopped/replaced request cannot begin late.
- Tests pending: deterministic activation ordering, cancellation/replacement, idle deactivation, source handoff, source integration guard, and fresh macOS/iPhone/iPadOS 27 builds.
- Next steps: implement one ordered audio-session transition boundary, route speech playback through an awaited request-owned activation gate, then complete regression and platform gates.

### 2026-07-21T14:40:50Z — implementation milestone

- Implementation: added one FIFO `AudioSessionCoordinator` for spoken playback, source preview, clip recording, and live recognition. iOS 27 uses async `activate`/`deactivate` with Boolean-result validation; iOS 17–26 uses the legacy blocking calls only on a private serial queue; macOS is a no-op.
- Lifecycle hardening: all three services now use pre-created owner tokens. Local and MiniMax playback, capture, preview, and recognition start I/O only after acquisition and reject stale/cancelled owners. Only the current owner may enqueue a real deactivation.

### 2026-08-06 — automatic AI analysis of newly saved words

- Request: add a toggle to the batch AI translation menu so that whenever a new word or phrase is added to the vocabulary list it is automatically processed by the selected LLM provider — translated and analyzed.
- Change: new opt-in `Auto-Translate New Words` toggle in the Batch AI Analysis screen, backed by `AutoAnalysisCoordinator` (an `@Observable @MainActor` background worker) over a pure `AutoAnalysisQueue` value type. `SavedTermsStore.add` notifies the coordinator from both overloads, so every capture surface (Translate, photo, reader, Shortcuts, import, menu bar) is covered by one hook.
- Design: the coordinator resolves the headword, reading, and gloss exactly the way `BatchExplanationController.preparePlan` does and writes to the same `WordExplanationCacheStore` key, so automatic and manual runs never duplicate each other and the batch screen's "Needs Analysis" count falls as the queue drains. The learning direction is resolved at dispatch, not at save time, so a word queued before a language switch is analyzed in the language now in force.
- Guardrails, because this spends tokens with nobody watching: off by default; deduplicated on the same normalized key the vocabulary and cache stores use; capped at 500 waiting words with refusals counted and reported; at most 3 dispatches per word; yields to a running reviewed batch; pauses itself after 3 consecutive failures and surfaces the error; both queue halves persist so a request interrupted by quitting resumes at the next launch; and it never touches the paid MiniMax speech pipeline (a check enforces that the file contains no audio reference in code).

### 2026-08-06 — record-and-transcribe repair (Multimodal audio)

- Report: record-and-transcribe in the Multimodal tab does not work; AI transcription is not using the selected audio model; the default Apple Speech recognition does not work.
- Root cause A: `AudioTranscriptionService` never installed the on-device speech model. The live dictation path modernized to `SpeechAnalyzer`/`SpeechTranscriber` and installs the locale asset via `AssetInventory`; the file path still used only `SFSpeechRecognizer` and installed nothing (`grep -c AssetInventory` — 1 vs 0). On iOS 26/macOS 26 an uninstalled locale has no working recognizer of either kind, so `isAvailable` stays false and the three-second poll fails. That is why live dictation worked and record-and-transcribe did not on the same device.
- Root cause B: `transcriptionProvider()` filtered the user's own selection through `supportsAudioTranscription` (true only for OpenAI, Qwen, Quotio), so a learner on any other provider had their recording uploaded to a different account they happened to hold a key for, or was refused outright.
- Change: the analyzer is now the primary file-transcription engine, installing the locale model first and reporting download progress; `SFSpeechRecognizer` remains for iOS 17-25 and as the fallback for locales the analyzer cannot serve; the on-device pass got its own 20-second deadline so a stall no longer delays the server retry by two minutes; `transcriptionProvider()` honors the selection and the pane names, in words, the provider the audio is sent to.
- Files: added `scripts/test-audio-transcription.sh`; updated `AudioTranscriptionService.swift`, `AIModelSettings.swift`, `MultimodalAudioInputView.swift`, `Localizable.xcstrings` (7 new keys with zh-Hans), `init.sh`, `README.md`, `README.zh-Hans.md`, `feature_list.json`.
- Tests: `zsh init.sh` green including the new 8/8 transcription wiring checks. macOS and generic iOS Simulator Debug builds succeed with zero warnings/errors. Four mutation tests confirm the checks fail when the asset install, the provider fix, the shorter deadline, or the provider name is removed. Localization coverage was re-verified with a corrected `.stringsdata` parser (the Iteration 30 parser read the tables as a dict when Xcode writes an array, so its "0 missing" result had been vacuous); all keys from both iterations are present and translated across 1,219 extracted keys.
- Not done: no device run and no live provider call. Qwen/Quotio ASR support remains documentation-derived; the change makes an unsupported provider report its own error rather than being silently swapped out.
